# 个性化旅游规划系统最终版本开发计划 V1.1

本计划基于 `mvp-v1.0` 继续开发，不推翻现有 MVP；论文材料暂不纳入开发范围。

## 最终范围

- 全国已知城市采用按需 POI 查询和景点知识构建，不预构建全国景点库。
- 浙江、云南、陕西作为省内多城市规划的重点实现和验收范围。
- 不实现跨省多城市、票务酒店预订、复杂预算、TSP/VRP、Multi-Agent。

## 开发顺序

1. 冻结并标记 MVP。
2. 升级结构化行程数据契约。
3. Route Tool 与行程集成。
4. Weather Tool。
5. Opening Hours 与 Visit Duration。
6. Schedule Builder。
7. Evaluator。
8. Replanner 与受影响数据重新补全。
9. LangGraph 有限反馈循环。
10. Redis 外部数据缓存。
11. `travel_plans` 版本化持久化。
12. 前端最终方案增强。
13. 异常降级与完整测试。
14. A/B 实验。

## 核心约束

- 路线查询使用已入库 POI 的经纬度，不根据景点名称重新猜测位置。
- 天气不可用时标记 `skipped` 或 `unavailable`，不让 LLM 猜测。
- 开放时间无法确认时标记 `unknown`，不能据此产生硬约束失败。
- Evaluator 的硬约束与严重程度分开表达。
- Replanner 只修改有问题的日期；修改后重新补全受影响的路线、开放时间和时间表。
- 自动重规划最多两次，超过限制后返回当前最佳方案及仍存在的问题。
- Redis 只缓存外部服务结果，MySQL 仍是主存储。
- 实验评分与系统内部 Evaluator 分离，避免系统对自身结果评分造成偏差。

## 每个模块的完成条件

每个模块必须明确输入、输出、调用方、外部依赖、异常行为、降级策略和测试，并在测试通过后使用中文提交说明单独提交。
